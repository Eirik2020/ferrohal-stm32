# FerroHAL: resolved debt

History: items moved out of [DEBT.md](DEBT.md) once done. Limits a fix left behind stay in DEBT.md as open items. Newest first within each section. Section numbers (§) refer to `ferrohal-architecture.md`.

## Crate-wide

- **The watchdog freezes under the debugger, can be windowed, and follows the board's LSI** (2026-11-09). `Watchdog::start` sets the per-chip `DBGMCU` freeze, so a halted core does not starve the counter; `start_windowed` (H7 only, `iwdg_v2`) resets a feed before the window opens; `start_with_lsi` scales the timeout to a measured LSI. IWDG-004 to IWDG-006, `src/iwdg.rs`; runs J on the F401 (50.09 ms for a nominal 50 ms) and K on the H753ZI (50.06 ms).
- **`Pwm::start_one_pulse` sends one period and stops** (2026-11-09). `CR1.OPM` clears the counter enable at the next update; a staged counter would stop at the latching update one tick in, so the start latches with `EGR.UG` while the mode is off, then enables it. The H753's TIM1 CH3N check samples one period at 1/4 duty and that the counter stopped itself: PWM-007, `src/timer_pwm.rs`; run J.

- **The I2C live path is verified on both Nucleo benches** (2026-11-08). A Pico 1 W (`hil/pico-i2c-sim`, RP2040) stands in for a real I2C device: two DW `apb_i2c` slaves at `0x2A`, one per bench (I2C0's GP0/GP1 on the F401's I2C3 PA8/PC9, I2C1's GP2/GP3 on the H753's I2C4 PD12/PD13 — the only instance each chip can free; `hil/WIRING.md` has the wiring and why each other instance is taken). Runs S drive the driver's ACK'd paths against it — 1-, 2- and 32-byte receives, a write that lands and reads back, a repeated start the slave observes, a stretch within the bound (the cycle floor proves it happened) and one past it (Timeout, then the stuck bus, then recovery), the data-phase refusal, the simulator's transaction count against the run's, the exact health totals, and the vacant address still nacking after all of it. The running scripted: `run-i2c-sim.sh` flashes the simulator and runs both benches. Found on the bench, all now part of the bench or the simulator: an **I2C pin must be `into_alternate_open_drain`** — push-pull AFs drive SDA high through every acknowledge and NACK every transfer to a live slave; a slave's **TX_ABORT flushes both FIFOs and holds them until `IC_CLR_TX_ABRT` is read**, so a second `respond_to_read` after the abort would push into a stopped bus — one call per read is the contract; the **DW never delivers a NACKed receive byte**, so the refusal is invisible on the wire and the simulator spends its arm on a timed warden instead; the **H7's v2 cannot see a held line** (its recovery clears ISR.BUSY), so the checks accept a bounded Timeout where the F401 reports Busy; and the **8-second watchdog** reboots the chip if a bus task wedges, with the warden feeding it only while both serve tasks are fresh. No finger on the button after the first flash: the map's `0x3D` BOOT register calls the bootrom's `_reset_to_usb_boot` through the public ROM table, and `run-i2c-sim.sh flash` sends it with run T when the RPI-RP2 drive is not mounted. The finding carried across to the fleet: every FerroWasp board wired its barometer bus push-pull (`into_alternate` on the Foxeer's PB8/PB9, the SpeedyBee's PB6/PB7 and the Lucid's PB10/PB11), which is exactly the defect the bench found — so no flight board's live I2C could ever have been acknowledged; all three now use `into_alternate_open_drain`. The same day it was proven end to end on hardware: the TBS Lucid H7's internal barometer — the DPS310/DPS368 family at `0x76` on I2C2, per its manual (chassis IDs 0x10) — went from `baro=0 baro_probe=2` on the old wiring to chip ID `0x10` read, coefficients loaded, and **101537 Pa at 3.0 °C** reported over the USB debug line: the first live I2C device on a flight board.

- **Every constructor hands its tokens back when it refuses** (2026-11-06). The last five — `Tick::new` and `Timebase::new` (the rate is checked before the timer is touched), `Watchdog::start` (a `Update` refusal leaves the watchdog running; only a reset stops it), `Sdmmc::new` (the clocks are checked before the peripheral is touched) and `UsbFs::new` — return `Refused` with everything they took, and the no-panic check retries each from the hand-back. With the UART, SPI, I2C, PWM, lane, sampler, generator, ADC and RCC constructors before them, nothing in the crate loses a token to a refusal.
- **The unbounded `Read::read`s say where the bound is** (2026-11-06). Both `embedded_io::Read::read` impls (`UartRx` and `Uart`) document [`UartRx::read_within`](crate::uart::UartRx::read_within) as the bounded form for FerroForge tasks.

- **The F4 clocks solve at compile time** (2026-11-06). `rcc_f4::Config::solve` takes a `Request` — the board's oscillator, the system frequency and, when the board has a USB or SDIO port, the frequency it needs — and computes the tree at compile time: the PLL input the oscillator's smallest division inside the chip's range (1 MHz on a whole-MHz crystal), the VCO the smallest that both the system clock (through P) and the USB clock (through Q, exactly) divide down from, and the buses' smallest prescalers inside their limits. What it returns always validates, so it always freezes; a request nothing meets is `ClockError::Unsatisfiable`, and one past the chip's limits is refused as ever. The rule is deterministic, and the host tests read it against the trees the benches freeze from — the F401's 84 MHz and the Foxeer's 168 MHz come out divider-for-divider. A board that wants a particular tree states it and `validate` checks it as ever.
- **The H7 clocks solve too** (2026-11-06). `rcc_h7rm0433::Config::solve` takes the oscillator, the system frequency and, when the board routes PLL1's Q to peripheral kernel clocks, that frequency — and computes the tree: the PLL input the oscillator divided as little as the 1 to 16 MHz range needs, the VCO the smallest that the system clock (through P, even) and Q divide down from, in whichever VCO range fits, and the prescalers the smallest inside the voltage scale's limits, with the scale the lowest voltage that supports the request. USB makes no request — it runs from HSI48. The host test reads it against the tree the Lucid freezes from (8 / 1 * 100 = 800 wide VCO, P 2, Q 8, Scale 1), with a 200 MHz request landing on the lowest voltage and one past 400 MHz refused.

- **The ADC wires up like the UARTs, and pins can be open drain** (2026-11-06). `adc::AdcWiring` carries one input's pin (in analog mode) and the DMA stream that serves the ADC, with `RESOURCES` stating the instance, the pin and the stream — `Resource::Analog` for a pin with no alternate function, and `Signal::Adc(channel)` naming it — and `channel()` gives the channel the pin measures, for `Adc::into_scan`'s runtime list. `gpio_v2` gained `into_alternate_open_drain`, for shared lines other devices hold or pull: I2C's SCL and SDA, which the I2C driver's branch will wire its pins with. The no-panic check converts a pin open drain on every chip, and the F401 chip test reads an ADC wiring's `RESOURCES` against the glue.

- **The clock tree and the ADC hand their tokens back too** (2026-11-06). `RCC::freeze` (both RCC IP versions) returns the RCC token: the configuration is validated before anything is written, so a refused configuration leaves the clocks alone, and a source that did not start is reported with whatever the attempt wrote in place. `Adc::new` returns the ADC token (the kernel clock is started, and the ADC may be enabled and reset, by the time a power-up refuses); `Adc::into_scan` returns the ADC, the stream and the buffer — the sequence and the buffer are checked, and the stream stopped through a second owner beside its token, before anything is consumed. The no-panic check retries each of them from the hand-back. What remains is in DEBT.md: `Tick::new`, `Timebase::new`, `Sdmmc::new`, `UsbFs::new` and `Watchdog::start`.

- **The timer constructors hand back their tokens when they refuse** (2026-11-06). `Pwm::new` returns the timer token (the rate is checked before the timer is touched); `PwmChannel::into_lane` and `into_two_way_lane` return the channel, the stream and the buffers (the stream is stopped through a second owner beside its token, so nothing is consumed until it succeeds); `Sampler::new` returns the timer, the stream and the buffer; `Awg::linked` and `Awg::independent` return both timers and both lane groups. Each refusal's parts retry unchanged, which the no-panic check does for every one of them, with a new `exercise_into_lane` on all four chips. The remaining refusers (`Tick`, `Timebase`, the ADCs, SDMMC, USB, the watchdog, `RCC::freeze`) stay in DEBT.md.

- **I2C master** (`i2c_v1`, `i2c_v2`, one driver). Both I2C generations behind one `embedded-hal` bus: the F4's SR1/SR2 events walked as RM0368 §27.3.3 sequences them (SB, ADDR with the one- and two-byte receive arming, the receive tail's NACK and stop taken with the last byte, BTF before a write segment's stop), and the H7's CR2 programs (NBYTES with RELOAD across chunks, AUTOEND on the last segment, the repeated start through the next START, flags cleared through ICR). The timing comes from the kernel clock — PCLK1 fixed on the F4, the I2C1235 and I2C4 muxes written by `freeze` on the H7 — and is unit-tested against RM0368's own worked example (FREQ 08, CCR 0x28, TRISE 09h). On hardware, both benches answer a vacant address: every kind of transfer NACKs within the driver's own measured bound, the bus recovers after each one, the timing registers read back as computed, a refusal hands the wiring back to be used, the health counts, and the counted bound ends without a clock.
  - Found on the bench: on the F4, a NACK recovery that cleared the flags and cycled PE left BUSY set — only a stop on the wire clears it (RM0368 §27.6.8), so the recovery arms one and waits bounded for idle. On the Nucleo-H753ZI, PB8/PB9 are the UART link Z4 and the fitted jumper shorts SCL to SDA (measured as a timeout with the clock held), so its run sits on I2C3 over PA8/PC9, the pair no other run links.
  - Byte transport for a device waits for the DPS310 wiring on the Foxeer; see `DEBT.md`.
- **Lanes wire up like the UARTs** (2026-11-06). `timer::LaneWiring` and `timer::ComplementaryLaneWiring` carry one compare lane's pin (in the channel's or the complementary output's alternate function) and its DMA stream, and their `RESOURCES` state the instance, the pin with its AF and the stream with its request, with `Signal::Channel(n)` and `Signal::Complementary(n)` naming the timer signals. `assemble` (and `assemble_two_way`, for a lane that also reads its own pin) builds the `CompareLane` from the wiring: the checks borrow the stream through the claim, so a refusal hands the wiring and the buffers back untouched and the retry takes them, as `Uart::new` does. The no-panic check exercises every assembly with the retry, and the F401 chip test reads a wiring's `RESOURCES` against the glue. The F405 glue gained `timer_trigger!(TIM2: TIM3, 2)` (with the F401's) so the SpeedyBee's four motor lanes can start from one edge — see RESOLVED's "One timer starting another".

- **The UART and SPI constructors hand back their tokens when they refuse.** `Uart::new`, `UartRx::new`, `Spi::new` and `BlockingSpi::new` return `Refused<ConfigError, P>`: the reason, and what they took by value (wiring with its instance, pins and DMA streams, and buffers), so a caller can retry or use them elsewhere. Printing one prints the reason alone, so bench logs read as before. Each constructor's checks borrow the parts and reach the streams through a claim that needs a key only FerroHAL makes, so nothing is consumed until it succeeds, and nothing outside can make a second owner. The hand-back is checked by the compiler, `Refused`'s host tests and the no-panic link check, which retries each constructor with the parts handed back; nothing runs a refusal. The other constructors still drop theirs (see DEBT.md).
- **The v2 parity-error clear** (`usart_v2`). RM0368 and RM0090 say to wait for RXNE before clearing PE, and the driver clears at once. Run B measured it each way at 115200: when a vector saw PE, RXNE was clear and the DMA already held the bad byte, so a wait would have stalled until the next byte. The next frame arrived intact, with one parity error reported. The driver stays as it was; the single speed stays in `DEBT.md`.
- **`freeze` writes the F4 voltage scale** (`RCC-003`). Scale 2 on the F401, scale 1 on the F405, with the PLL off, and it waits for VOSRDY before switching to the PLL. Both benches set a lower scale first and read back that it was replaced: 0b01 to 0b10 on the F401, 0b00 to 0b01 on the F405.
- **No reachable panic, proven per chip** (§5, §13). `checks/no-panic` calls every public UART, DMA, GPIO and RCC operation with optimiser-opaque inputs under a panic handler that calls an undefined symbol, so the release build links only if no panic path survives. It found five metapac bounds asserts (fixed by masking stream indices) and two divisions in the H7 clock check (now `checked_div`). It covers all four chips.
- **Lap detection counts pending flags** (`write_count`). `read` adds the receive stream's unserved half and complete flags to the interrupt's count, so the interrupt may be almost a full lap late, not half. The HIL check "receive interrupt late by most of a lap" fails without the fix and passes with it, on both benches.
- **Errors keep their place in the stream.** The interrupt records each line error and idle line as a mark at its ring position; `try_read` returns the bytes before an error first and the error next; `read_chunk` ends the struck chunk with `ChunkEnd::Gap`.
- **Waits last the time asked, given a caller clock.** With a `CycleClock` (e.g. DWT), `read_within` lasts 1.2 times the 8N1 frame time on every board.
- **FerroWasp's transfer model, natively** (§11, §15). Receive: the ring never stops; `read_chunk` gives idle-ended, buffer-full and gap-ended chunks with a generation counter and `Health`. Transmit: `try_send` queues whole frames (up to 8, contiguous); the TX DMA interrupt chains them, or polling does. `TxHealth` counts frames, DMA errors and timeouts. The task/`UartIrq` protocol (`servicing`, `deferred`) was found on the bench to need fixing twice (an interrupt storm, then a CR read-modify-write race) and was.
- **Receive-only UARTs and inversion.** `UartRx::new` opens a UART with no TX pin or stream. RX/TX inversion are `Config` fields; `usart_v4` sets RXINV/TXINV, `usart_v2` refuses them. H753ZI run E receives the Lucid's SBUS case from inverted bit-banged frames; F401 run D receives plain SBUS.
- **Interrupt requirements are checked** (§7 hook 1). `UartIrq::interrupts()` names the vectors; `verify()` reads the NVIC and reports a disabled vector or mismatched priorities. Every bench firmware checks it, and that a masked receive vector is caught.
- **Resource descriptors.** `Wiring::RESOURCES` and `RxWiring::RESOURCES` list the USART, pins (port, number, AF), DMA streams (controller, stream, request) and vectors as `const` data, for comparison with a board manifest. Each chip's host test checks one wiring against FerroWasp's manifest where there is one.
- **Chip glue holds facts only.** Shared shapes (tokens, `Peripherals`, pin rows, stream vectors) are macros in `src/chips/shared/macros.rs`; what the RM0433 chips share (clock limits, DMA-reachable RAM, MPU walk) is `src/chips/shared/h7.rs`.
- **Routing tables are checked** against metapac by `tools/check_glue.py` (planted errors in AF, stream, RCC bit, DMAMUX request, extra pin or DMAMUX base all fail it).
- **The crate is in git** (its own repository, `ferrohal-stm32/`).
- **SPI master over DMA** (`spi_v2`, `spi_v4`, one engine). `start`/`on_interrupt`/`poll`/`received`/`abort`, a bounded blocking `transfer` and `embedded_hal::spi::SpiBus`; the receive stream's vector only. On hardware: every SPI pin entry and SPI DMA route on the F401, SPI1 to SPI5 on the H753ZI's Zio pins, each with loopback by interrupt and by polling, `SpiBus`, refusals, all four modes with SCK idling at CPOL, 8 SCK edges per byte counted by EXTI on the SCK pin, transfer time against the reported SCK, and abort then a clean transfer.
  - Found on the bench: `spi_v4` set MASTER with SSI still 0, so a mode fault cleared MASTER and no H7 transfer ran; SSI is now set first. `spi_v2` (SPE stays on) left the frames in flight at an abort to land in DR, so the next transfer received a stale byte first; `reset_state` now waits for the bus to go idle before draining DR.
  - Errata applied: ES0299 2.11.1 / ES0182 2.12.1 (SPE stays on, F4); ES0392 2.22.2 (SPE per transfer), 2.22.5 (CRCSIZE 7), 2.22.6 (one SCK held after EOT) on the H7.
- **EXTI** (`exti_v1`, `exti_h7`, one source): typed line tokens, `Ctrl` owning the shared registers, routing without taking the pin, a `Copy` handle for handlers. On hardware: rising, falling and both edges, masked lines, software trigger and level reads on both boards. A masked line doesn't latch its edges (RM0368 10.2.4, RM0433 20.3.1; the first doc said otherwise and the F401 corrected it).
- **Timers, as counters** (`timer_v1`, `timer_v3`, one source). `Tick`: the update interrupt at an exact rate, PSC and ARR from a `const fn`. `Timebase`: a 32-bit timer counting freely at an exact frequency, with a `Copy` reader. `Clocks::timer(bus)` gives the timer clock (twice the bus clock behind a dividing prescaler). The glue's `timers!` rows (bus, enable bit, update vector, width) are checked against metapac. On hardware: every timer on both Nucleos ticks at 1 kHz to 0.05 % of the DWT and stops when paused; TIM4 at 8 kHz; TIM2 and TIM5 as 1 MHz timebases to 0.01 %.
- **Timer outputs and timer-paced DMA** (`timer_pwm.rs`, both IP versions). `Pwm` (nearest rate, reported; `set_frequency`), `PwmChannel` on CHx or CHxN (MOE set on break-unit timers), `CompareLane` (a channel's compare register fed by DMA, paced by its compare request: the DShot transmit primitive, staged and started as FerroWasp does) and `Sampler` (a port's input register copied by DMA at a timer's update rate: the DShot receive primitive). Glue rows for channel counts, break units, CHx/CHxN pins, compare and update DMA routes and the GPIO-reaching streams, generated from and checked against metapac (82/128/129/132 facts). On hardware, read back by samplers: two lanes per timer sending 16-bit patterns from one update at the DShot150, 300 and 600 rates, every bit and period right, on the F401 (TIM3 on DMA1) and on the H753ZI (the Lucid's TIM3 lanes on its streams, and TIM5); TIM1 CH3N at its duty on the H753ZI.
  - Found on the bench: nothing in the driver; the check's sample window started before the lanes were armed and cut DShot600 frames short, so it now starts last.
  - The no-panic check caught a division in `nearest` the optimiser couldn't prove safe.
- **Independent watchdog and reset cause** (`iwdg_v1`, `iwdg_v2`, one source). `Watchdog::start(token, timeout_us)` (prescaler and reload from a `const fn` at the nominal LSI), `feed`; `Rcc::reset_cause()` reads and clears RCC's reset flags into a chip-neutral `ResetCause`. On hardware, across the reset it causes: fed every 10 ms a 50 ms watchdog never fires; starved, it resets the chip, the reset cause reads back as the watchdog, and the reset lands within the LSI's spread (F401 53.3 ms, H753ZI 50.5 ms).
- **Polled SPI** (`BlockingSpi`, both IP versions): a bounded `SpiBus` with no DMA, one byte in flight. Needed by the Foxeer's NOR on SPI2, whose only streams (DMA1 3 and 4) its UARTs hold. On hardware: SPI2 on the Foxeer's NOR pins and SPI3 on the F401, SPI2 and SPI4 on the H753ZI.
- **SPI wait floor measured:** `PASS_CYCLES` from a guessed 8 to 112, half the fastest pass measured (233 cycles, H753 with caches on).
- **USB CDC** (`usb` feature): `UsbFs` gives `synopsys-usb-otg` the chip's facts, for `usb-device` and `usbd-serial`, the stack FerroWasp already uses, on all four chips. `Rcc::usb_clock` checks PLLQ on the F4 and starts HSI48 and the USB supply on the H7. On hardware (H753ZI, CN13): the host configures the device, and blocks of 1 to 4096 bytes and 64 KiB echo correctly at 561 KiB/s.
  - Found on the bench: the H7's OTG2 is the high-speed-capable core, so it needs the crate's `hs` mode to select its internal full-speed PHY; without it the core reset hangs for ever. Charge-only cables give VBUS and no data, which looks just like a dead port.
- **Shared types:** `resource::{Resource, Signal, IrqError}` for every driver (`Resource::Uart` became `Resource::Peripheral`), `time::CycleClock`, and the bounded waits in `wait`.

## STM32F405RG

- **Values checked against the docs** (RM0090 Rev 22, DS8626 Rev 12, ES0182 Rev 19 in `docs/stm32f405/`):
  - DS8626: HCLK 168 MHz (VOS 1; 144 MHz with VOS 0), PCLK1 42, PCLK2 84; HSE crystal 4–26 MHz, external 1–50 MHz; PLL input 0.95–2.10 MHz; VCO 100–432 MHz.
  - RM0090: PLLM 2–63, PLLN 50–432; wait states (table 11) 30 MHz per WS at 2.7–3.6 V, 5 WS for 150–168 MHz; VOS is PWR_CR bit 14, reset value 1 (scale 1); SRAM1 + SRAM2 at 0x2000_0000 for all AHB masters, CCM at 0x1000_0000 CPU-only; 0.5 and 1.5 stop bits unavailable on UART4/5 (30.6.5).
- **UART4/5 reserved bit.** SR bit 9 (CTS) is reserved on UART4/5 (RM0090 30.6.1); `clear_tc` wrote 1 there and now writes 0, which is also right on the USARTs since CTS is only set with CTSE on.
- **Errata review** (ES0182): 2.2.13 RCC enable delay handled; 2.2.1 (prefetch, rev A), 2.2.19 (DMA2 AHB/APB2), 2.11.1 (IDLE), 2.11.2 (PE) tracked in DEBT.md. Not applicable: 2.2.11 (APB slowed during DMA: clocks are set once, before any driver), 2.6.1 (DAC), 2.11.3–2.11.8 (mute mode, CTS, smartcard, NACK, guard time, CTS with break: none used).
- **UART4 and UART5.** metapac 21 types them as `usart::Usart`; 0.5 and 1.5 stop bits are refused per instance (`Instance::FRACTIONAL_STOP_BITS`) by `Uart::new`, `UartRx::new`, `set_config` and `Uart::check`.
- **CCM RAM is refused for DMA:** `check_dma_buffer` accepts SRAM1 and SRAM2 only (0x2000_0000, 128 KiB).
- **Runs on hardware** (2026-11-02, `hil/run-foxeer.sh`, 28 of 28 and the host's echo up to 64 KiB, at 561 KiB/s), on the Foxeer F405 V2 over its USB port, flashed through the ROM DFU bootloader:
  - **HSE with a crystal:** 8 MHz to 168 MHz. RCC agrees, and the CPU counts 167.9 million cycles per 1000 host USB frames, the one clock not from the crystal.
  - **The SPI NOR on the real chip:** Winbond JEDEC ID `ef 40 18` at 10.5 MHz over `BlockingSpi`. Erase (47 ms), 16 pages programmed (slowest 379 µs), read back, erased again, only in FerroWasp's scratch sector; the sectors either side unchanged.
  - **The IMU path:** ICM-42688-P WHO_AM_I over SPI1 on DMA2 streams 3 and 0, then FerroWasp's setup: 405 data-ready edges in 200 ms on EXTI4, 400 bursts of 15 bytes at 10.5 MHz started from them (slowest 24 µs, none failed or missed), the accelerometer reading 993 mg at rest.

## Restarting into the ROM bootloader

- **`reset::reboot_to_bootloader`, `bootloader_requested`, `enter_bootloader`, `peek_cause`** (2026-11-02), for the F4 and H7, with the chips' system memory addresses and the F4's memory remap in the glue. Run L on the F401, run N on the H753ZI: the request survives a software reset, with the data cache off and on, and answers yes once. The Foxeer's bench enters its ROM DFU through it.
- **Found on the Lucid:** a single word written to AXI SRAM just before a reset is lost (RM0433 2.4; ECC per 64 bits). The bench measured a lone word, a barrier and a read back all lost; a whole doubleword or a further write kept. The F4's RAM has no ECC, so its benches never showed it.

## SD cards

- **`sdmmc::Sdmmc`** (2026-11-02), on `sdmmc_v2`: a 16 GB SanDisk in the Lucid, at 25 MHz on 4 bits, reads and writes one block and sixteen in one command (16 blocks: about 5 ms to write, 0.9 ms to read), and has the blocks it borrowed restored. A read waits for the end of data, where a CRC error on the last block shows.

## USB from its interrupt

- **`OTG_FS` under RTIC at priority 5** (2026-11-02), FerroWasp's arrangement, on the Foxeer and the Lucid: the host's echo up to 64 KiB, at the polled rate. The firmware services USB only from that vector.
- **VTOR after a DFU `leave`:** the F405's ROM jumps to the application with no reset, leaving VTOR on the ROM, so the firmware's first interrupts ran the ROM's USB handler. The control run proved it: the same firmware without `set-vtor` gets STALLed descriptor reads and `unable to enumerate`; with it, it echoes up to 64 KiB. FerroHAL's `rt` feature now turns `set-vtor` on, for every firmware.
- **`reset::enter_bootloader` hands the ROM a clean core:** SysTick off, every NVIC line disabled and cleared, interrupts unmasked. RTIC's `init` runs masked with its lines enabled, and the ROM's USB needs interrupts: without this the board came up in the ROM but never enumerated.

## ADC and unique ID

- **`adc::Adc` and `AdcScan`** (2026-11-02), on `adc_v2` and `adc_v4`: ADC1 and, on the H7, ADC3, read one at a time or as a sequence over DMA. Run M on the F401, run O on the H753ZI, and the Foxeer's battery inputs in FerroWasp's sequence (temperature, voltage, current; 77 µs at the slowest). ## One timer starting another

- **`Pwm::lead` and `Pwm::follow`** (2026-11-02): FerroWasp's Foxeer starts TIM8 from TIM1 so all four lanes begin on one edge. Run N on the F401 (TIM1, TIM3), run P on the H753ZI and the Foxeer's own check (TIM1, TIM8): the slave waits, starts every time over 100 starts, and reads within 3 or 4 counts of the master, read one after the other. No output is enabled in any of them.
- **TIM3 starts TIM2 on the F4s** (2026-11-06): the SpeedyBee F405 V5's motors sit on TIM3 CH3/CH4 (PB0/PB1) and TIM2 CH3/CH4 (PB10/PB11), so its bank needs TIM3 leading TIM2 the way the Foxeer's TIM1 leads TIM8. The glue gained `timer_trigger!(TIM2: TIM3, 2)` on the F401 and the F405 (RM0090 table 94, RM0368 table 54: TIM2's ITR2). Run R on the F401 drives the SpeedyBee's four lanes at the DShot600 rate from one start — TIM2 in software beside TIM3, then from TIM3's trigger, then every lane active low as bidirectional DShot idles the line — all read back by the TIM1/DMA2 port-B sampler, 18 checks. It rides TIM2 CH2 on PB3 for the second TIM2 lane: the board's TIM2 CH4 pin, PB11, is not bonded on the F401's LQFP64 (DS10086's pin table), and the lane's DMA route, stream 6 channel 3, is the same one CH4 uses. `trigger_suite`'s first check now asks only that the slave is not running, not that its counter reads zero — a stopped timer keeps its count, and run R's slave arrives having run. Run N is unchanged and still passes.

## STM32H753ZI

- **HSE in bypass runs on hardware.** Run A, the Lucid mirror, freezes from the ST-LINK's 8 MHz MCO (UM2407 7.5.1): 8 MHz reference, 800 MHz wide VCO, 400 MHz core.
- **The D-cache can be on.** With it on, `check_dma_buffer` requires each buffer to lie wholly in one enabled MPU region with non-cacheable attributes (TEX, C, B; subregions honoured) that no higher region overlaps. The HIL turns both caches on with buffers in a non-cacheable `DMA_NC` block, and checks that cached RAM and the DTCM are refused.
- **Errata covered:** ES0392 2.20.4 (USART DMA lock-up; TRBUFF set on every UART transfer), 2.5.4 (DMAMUX routing; SE stays 0, SPOL 00).
